# ADR：目录浏览与领域加载分离，错误保留现场

## 背景

项目目录打开曾耦合核心 JSON、机制/视图、默认或最近图和附属初始化；一个坏文件即可阻断导航。连接失败后的自动刷新还会抹去错误与草稿，使故障表现为静默失败。

## 决策

- `POST /api/project/directory` 只枚举 `.mechanics` 的文件和目录，不解析 JSON、不迁移、不初始化、不更新技能、不恢复默认/最近图。目录投影返回 `navigationOnly` 与逐路径 diagnostics，不伪造领域对象，不获得领域写入能力。当前网页打开项目与启动恢复在目录前执行共享准备入口，目录后自动尝试领域加载并进入[固定总览](2026-10-29-session-overview-and-force-layout.md)；额外阶段不改变目录接口自身的只读边界。
- 目录呈现后使用独立只读 `POST /api/project/metadata` 回读磁盘 `workspace.json.name`，只检查安全读取与名称形状，不进行全工作区领域校验。名称失败明确报告并保留目录与文件夹标识，不能把后备标识冒充已保存名称；异步响应按当前目录对象身份隔离，已经切换项目或进入领域会话时不再应用。设置提交成功后同步同根工作区/源项目/浏览快照和文件标签，避免另一份 UI 快照成为名称事实源。
- 领域加载成功后才进入领域会话；自动加载和显式打开文件都遵守同一校验。核心损坏不阻断独立目录浏览，但领域加载必须明确失败；不能以默认 definitions/rules 掩盖损坏。
- 在支持逐资源隔离的领域读取中，字节读取与 JSON 解析和资源校验同属机制/视图隔离边界；失败资源保留诊断，不当作有效图。默认严格读取与保存门禁不放宽。
- 连接失败、响应解析失败或超时不得推定服务重启并自动刷新。打开失败保留目录与现场，写入响应丢失仍报告结果待确认，要求核实而非重放。

## 备选方案

不采用目录枚举与领域解析不可分割的入口，避免坏规则使文件导航完全失效。初版要求用户显式加载，当前改为目录保底后自动尝试加载总览，不恢复最近图。

## 后果

目录可浏览不等于项目数据有效或可编辑。独立目录接口保持无附属写入，完整打开流程可执行准备与领域加载。链接不跟随，目录深度与数量限制仍执行，无法读取的路径明确报告；不承诺不可访问根目录也能成功浏览。

## 实现与验证

实现入口：`src/server/workspace.mjs`、`src/server/http.mjs`、`src/web/app.mjs`。2026-10-12 完成记录确认 `npm run check` 615 通过、2 跳过，`check:package` 通过；实际项目目录打开成功，隔离浏览器验证坏核心可浏览、图失败保留目录与明确错误、修复后健康图可打开且无页面错误。测试数字是本次记录，不是未来环境保证；未修改游戏 canonical JSON。
